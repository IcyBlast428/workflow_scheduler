# 验证范围与首次投产验收

## 已有证据

用户在 2026-11-18 确认当前稳定版本已在生产运行。此前反馈显示任务已成功发布，在页面补充 Jinja2 后执行成功并启用调度。这覆盖该现场任务的实际链路，不代表所有任务、数据库适配器、负载、故障恢复和备份恢复均已验收。助手没有直接登录生产服务器或访问内网数据库。

开发回归使用隔离 PostgreSQL，覆盖事务、CAS、队列、发布和权限等；浏览器测试使用本机服务与模拟 GitLab。部署工具测试验证配置保留、安装顺序与文件完整性。它们不能代替 GaussDB/DWS 的实际产品版本、ODBC 驱动和网络验证。

## 新环境验收顺序

1. 确认 Linux/Python/驱动版本、平台库 `immpdb` 和专用空 schema `wfs`（或本次约定名称）。
2. 执行发布包校验；完成初始化 32 张表，确认数据库账号权限。
3. 检查唯一 `wfs.service`、Web 与单实例 Scheduler 就绪，验证代理登录。
4. 配置 GitLab 和 Nexus，发布低风险任务，核对依赖锁定、日志、输出和实际业务结果；完成后启用计划。
5. 按业务需要另行验收数据库授权、事务、超时、重启、断库恢复、容量及原生备份恢复；结果不确定的任务不自动重放。

后端开发回归入口 `python scripts/test_backend.py`、浏览器入口 `python scripts/run_browser_tests.py` 只能在隔离开发环境运行，不在生产执行测试。历史检查记录见 [架构检查](../../docs/fresh-gauss-audit.md)，首次操作见 [投产手册](../../START-HERE.md)。
