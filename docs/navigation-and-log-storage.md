# 导航与执行日志管理

主侧栏保留总览、任务列表、执行矩阵、执行记录、代码更新。执行队列已并入执行矩阵的管理员分栏，原 `#queue` 地址仍可打开。左下角账户菜单中的管理员入口包括平台设置、平台事件、任务示例与文档；普通用户不显示管理员入口。

平台设置分为运行与发布、连接与依赖、账户与权限、审计与存储。原来的 `#connections`、`#repository` 和 `#admin?section=storage` 链接仍可使用。任务列表仍保留任务示例入口；服务异常时顶部提供平台事件入口。

## 后台更新与执行记录

总览、矩阵、队列和代码更新的定时请求保留当前内容，不切换到手动加载状态。首次加载、主动查询和明确错误仍有反馈。

执行记录通过现有事件摘要每 5 秒检查变化。已有记录时，新结果只触发“有新执行记录”提示，不替换当前行、焦点、分页和选中内容；点击后回到第一页读取最新结果。空列表出现首条结果时自动显示。非当天和归档查询不自动跟随；已编辑但未提交的搜索条件不会被后台请求自动应用。一次提示后停止重复查询记录正文，直到用户主动更新。事件摘要和后端缓存可能带来数秒延迟，不是逐条推送。

## 大日志查看

执行详情默认读取文件末尾最多 64 KiB，避免从文件开头逐段追赶。可以查看日志开头、较早一段、较后一段，或回到最新日志。查看历史分段时暂停轮询追加。页面缓存不超过 256 KiB，搜索只针对当前加载的内容；完整保留日志通过下载读取。

历史记录中的数据库日志正文预览在 SQL 查询时限制为末尾 65536 字符，避免将旧版本写入的超大正文完整传输到浏览器。这不会修改数据库原文。

## 手动清理

入口：Admin → 平台设置 → 审计与存储 → 存储清理与备份 → 执行日志清理。

1. 设置至少保留的天数（7–3650 天），点击预览。
2. 核对截止结束时间、本批条数和预计释放空间；需要留档的日志应先下载或备份。
3. 输入完整确认文字后执行。每批最多 500 条，预览计划十分钟有效。完成后再次预览下一批。

只清理已结束、元数据已同步且历史保存完成的执行日志文件。排队、运行、待补写、近期结束的执行受保护；外部路径、链接和预览后发生变化的文件会跳过。执行记录、统计、历史摘要、业务输出和代码版本不随此操作删除。重复提交计划会跳过已清理的执行。清理结果写入审计记录。

扫描限制为最多 5000 条索引并有时间上限，页面标示本批检查结果，不代表磁盘全部占用。已清理标记保存在执行元数据中，详情页明确提示文件已清理。

## 自动保留与容量

已有后台日志保留期由部署环境变量 `WFS_LOG_RETENTION_DAYS` 管理，默认 90 天，下限 60 天；手动清理天数不会改变这个配置。单次执行的文件输出日志上限由 `WFS_RUN_LOG_MAX_BYTES` 管理，默认 5 MiB。现有清理不包括数据库旧日志正文、业务输出或 systemd 日志；数据库历史归档和服务日志轮转应分别管理。

本机 PostgreSQL 回归验证不等于生产 GaussDB/DWS 验收；部署时还需核对实际共享目录权限、IO 和保留要求。
