## 四项后续优化（2026-11-15）

按确认继续处理前四项，旧接口、历史任务 SDK、部署入口及数据库驱动均保留。

1. 浏览器可见性和联网事件由共享生命周期协调；轮询资源各自负责恢复，平台事件等非轮询页面也保留恢复读取。用户资料就绪后只读取当前工作区所需数据，手动刷新和操作后的明确刷新继续生效。App 的相关逻辑抽到 `useWorkspaceRefresh`。
2. 从执行矩阵或历史记录打开详情时，首次请求直接读取末尾日志并交给详情弹窗，避免立即重复读取。运行中执行从返回的偏移继续读取；关闭后的迟到响应不会重新打开弹窗。重新打开读取新数据，HTTP 400/404 仍回退到原历史日志接口。
3. 六小时资源历史采用 `metrics.jsonl` 增量追加，每条采样同步落盘，每5分钟原子压缩。已有4,320条样本约241,920字节时，再采10条仅追加560字节；兼容并保留原 `metrics.json`，恢复及回退说明见 [资源曲线保存](runtime-scale-improvements.md#资源曲线的增量保存)。
4. `ScheduleDialog.vue` 从794行拆到189行，任务设置、执行策略和未来执行预览各自独立；父弹窗仍统一维护草稿、变更保护、预览防抖和提交。`CpuTimelineChart.vue` 从821行拆到489行，数据归一化/轨道布局与视窗交互分别独立，保留SVG和样式。
