# 可视化流程任务设计草案

状态：按用户要求暂缓，保留设计提案，尚未接入当前服务。日期：2026-09-30。

## 1. 产品目标

用户在页面选择常用能力、配置参数、连接节点，将整个流程作为一个任务定时或手动执行。已有 Python 脚本任务继续使用；新流程可通过“运行已有任务”节点复用它们。

示例：每分钟检查积压 → 查询业务数据库 → 判断积压量 → 超阈值生成邮件并发送短信，未超阈值正常结束。另一示例：每天查询报表 → 格式化内容 → 发送邮件。

任务列表增加“脚本 / 流程”类型、发布版本和“编辑流程”入口；保持原有调度、手动触发、暂停、强停和运行记录操作。

## 2. 页面布局与操作

- 左侧：节点库，按触发、数据、判断、通知、脚本分类；搜索和拖入画布。
- 中间：流程画布，拖动节点，从输出端口连到输入端口；支持缩放、撤销、复制、自动排列和错误定位。
- 右侧：当前节点配置、可用上游字段、输入/输出样例；高级配置集中在折叠区域。
- 顶部：名称、草稿/已发布状态、版本、保存草稿、校验、模拟运行、发布；调度作为整个流程的配置。
- 底部：本次运行节点时间线；点击节点查看状态、耗时、输入摘要、输出摘要和失败原因。

右侧面板示例：

1. 查询节点：连接“业务 GaussDB”、SQL、参数、最大返回行数、超时；“测试连接”和“预览查询”。
2. 条件节点：从变量选择器选 `查询积压.rows[0].pending_count`，选择“大于”，输入阈值；输出端口“满足 / 不满足”。
3. 邮件节点：选择 SMTP 连接、收件人组、标题和正文模板；模板通过变量选择器插入数据。
4. 短信节点：选择短信网关、收件人组、内容模板；显示预计条数和长度。

字段引用同时显示人类可读名称和稳定节点 ID；节点改名不会破坏绑定。必填项、类型和不可用变量直接定位到对应节点。模拟运行后的值可以展开检查。

## 3. 第一版节点

| 节点 | 配置 | 输出 |
| --- | --- | --- |
| 开始 | 运行参数；实际触发由现有调度器负责 | 运行 ID、触发时间、参数 |
| 数据库查询 | 业务连接、参数化 SQL、超时、行数上限 | rows、row_count、columns |
| 条件判断 | 字段、运算符、常量/变量 | 满足或不满足 |
| 内容模板 | 文本/HTML模板、上游字段 | text 或 html |
| HTTP 请求 | 连接、方法、路径、参数、状态码规则 | status_code、经过限制的响应数据 |
| 发送邮件 | SMTP 连接、收件人组、标题、正文 | 网关接受结果、可用的消息 ID |
| 发送短信 | 网关、收件人组、模板 | 网关接受结果、可用的消息 ID |
| 运行已有任务 | 已登记 Python 任务、超时、结果映射 | 退出码、日志引用；结构化输出需额外约定 |
| 结束 | 结果摘要 | 流程完成 |

第一版以“串行步骤 + 条件分支”的无环图为范围。每个普通节点最多一个入边和一个后继；条件节点必须明确两条分支，每条分支独立结束。第一版不允许多分支合流、任意循环或并行执行。

第二版增加有次数上限的逐条处理、数据库写入节点、CSV/Excel、文件附件、子流程与模板市场。第三版再增加并行、显式合流策略、事件触发和分布式执行。数据库写入必须明确事务边界；邮件、短信等外部动作不能随数据库回滚一起撤销。

“运行已有任务”先复用原脚本，后续提供页面代码编辑器：工作副本、检查、试运行、发布固定代码版本，运行中的版本保持不变。代码修改权限独立管理；Python 子进程资源限制不能视为不可信代码沙箱。

## 4. 连接中心与复用

数据库、SMTP、短信和 HTTP 认证集中配置为“连接”，节点只保存 connection_id。数据库连接在具体执行时打开并关闭，连线传递查询结果等数据，不传递活的 connection 对象。

连接记录保存名称、类型、非敏感配置、密钥引用、负责人和可使用范围。凭据保存在服务端密钥配置或 Nacos；页面和流程导出不返回明文。测试连接默认只检查可达与认证；真实邮件/短信测试需要专门测试收件人。

平台日志数据库和业务连接使用独立配置与授权。首批业务查询支持 GaussDB/PostgreSQL，已有 MySQL/Oracle/ClickHouse 适配器经节点契约验收后接入。数据库查询默认使用具有只读权限的业务账户；不以 SQL 文本前缀检查代替数据库权限。

## 5. 执行规则

### 版本与校验

- 编辑产生草稿；保存有 revision 冲突检查。
- 发布产生不可修改的版本，保存图结构、节点配置、节点实现版本和引用清单。
- 执行开始时固定流程版本、代码版本和非敏感配置快照；密钥通过引用解析，不把明文写进快照。轮换凭据无需复制到每个节点。
- 发布校验：唯一开始、终止路径、无环、无悬空端口、节点 ID 唯一、分支齐全、连接可使用、必填参数和类型合法；引用的数据必须在该分支上已产生。

### 数据契约

- 节点输入/输出定义 schema；日期、Decimal、空值等统一序列化。
- 连线控制执行顺序；具体输入通过字段映射明确绑定。条件使用受限运算符，模板使用字段引用，不执行任意表达式。
- 初始建议默认查询最多 1000 行、输出预览 20 行；这些是可调整的设计默认值，需容量测试确定最终上限。
- 大结果写入受控文件/对象存储，节点间传引用；不会把大量行数据反复复制到运行表和日志中。

### 超时、失败和重试

- 复用当前任务级并发、超时、强停；增加节点超时和取消检查。流程内多个节点不会自动增加全局任务名额。
- 状态：等待、运行、成功、失败、跳过、已取消、重启中断；未走到的条件分支显示“跳过”。节点日志按 run_id、node_id、attempt 查询。
- 第一版默认失败即停止，并执行单独配置的失败通知；保留原始错误，避免失败通知递归触发。
- 只读查询/读取请求允许有限次数重试与退避；邮件、短信、写库、调用已有任务默认关闭自动重试。超时可能意味着外部动作已经执行，状态记录为“结果待确认”，不能直接当作未发送。
- 去重键使用运行、节点和业务键；只有网关/业务操作提供幂等支持才能保证对应效果。服务重启后把运行标记为中断，第一版不自动从中间恢复有副作用的步骤。
- 分钟级告警可配置“只在状态变化时发送”和冷却时间，防止同一异常每分钟重复通知。

### 模拟运行

默认使用样例或上次脱敏输出：查询节点提供模拟数据，邮件/短信/写入/有副作用 HTTP 节点只生成动作预览。真实只读查询预览单独点击、限时限量；真实动作测试明确目标并单独运行。模拟结果有显著标记，不写成真实业务成功记录。

## 6. 与当前代码的接入

当前项目已具备单实例 Scheduler、独立任务子进程、持久化运行记录、配置版本和角色权限；这一方案复用它们。

```text
Vue 流程编辑器
   ↓ 保存草稿 / 校验 / 发布
Flask 流程 API → 平台 GaussDB 的流程版本
   ↓ 手动或定时触发
现有 Scheduler → 统一任务执行入口（script / workflow）
   ↓
独立流程 worker → 节点注册表 → 业务连接与公共能力
   ↓
运行摘要 + 节点状态 + 有界日志/数据引用
```

- `frontend/src/`：新增流程列表、画布、配置面板、变量选择器、运行视图。画布候选为 Vue Flow，自定义节点、连线、缩放等现成能力见官方文档：https://vueflow.dev/guide/ 。依赖打包进现有前端，生产运行不依赖 CDN。
- `app/api/`：新增流程 CRUD、revision 检查、validate、publish、preview 和运行详情 API。
- `app/bootstrap/execution.py`：增加统一 execute_task 分派，保留 execute_py 兼容入口；流程使用独立 worker。流程不能直接占用 Web 请求线程执行。
- `app/bootstrap/schedule_config.py` 与任务发现：从文件脚本和已发布流程两种来源生成统一任务描述。流程任务 ID 独立命名，避免与目录任务混淆。
- 新增 `app/workflows/`：图校验、解释执行、节点契约、节点注册表、连接解析、模板映射。
- `app/common/db/`、`mail.py`、`sms.py`：适配为统一输入/输出/错误契约；短信当前只检查 HTTP 状态且可能返回 False，需要解析网关业务应答。邮件发送部分拒收也必须反馈，网关接受不能显示为最终送达。
- `migrations/`：新增向后兼容迁移。设计阶段不改现有表或在线服务。

## 7. 建议数据模型

| 表 | 用途 |
| --- | --- |
| wfs_workflows | 流程元信息、任务 ID、草稿 revision、当前发布版本 |
| wfs_workflow_versions | 不可变图定义、节点配置、格式版本、发布人、校验值 |
| wfs_connections | 连接类型、非敏感配置、密钥引用与使用范围 |
| wfs_workflow_node_runs | run_id、node_id、attempt、状态、时间、错误分类和数据引用 |
| wfs_workflow_artifacts | 有界输入/输出预览、文件引用、大小和保留期限 |

流程整体运行继续进入现有 `wfs_executions` / `wfs_run_history`，节点级详情单独查询。常用索引以 `(run_id,node_id,attempt)` 和时间为主；节点明细与产物也制定归档/删除策略，避免 200 万次运行乘以节点数后无限增长。默认只保存元信息和脱敏摘要，完整产物按需开启。

流程图按带 schema_version 的 JSON 文本持久化，节点类型带实现版本。第一版避免依赖 PostgreSQL 专有 JSONB 操作，以便在实际 GaussDB 验证迁移和读取。

## 8. 落地顺序与验收

1. 编辑器与连接中心：建流程、配置节点、连接、校验、保存草稿；无外部真实动作。
2. 最小执行闭环：固定发布版本，手动执行数据库查询 → 条件 → 模板 → 模拟通知；查看节点输入/输出和错误。
3. 接入真实通知与现有脚本节点，复用调度、取消、超时、角色和审计；用本地 PostgreSQL 做真实连接测试。
4. 在真实 GaussDB 与测试通知网关验收：断网、超时、取消、服务重启、发布冲突、重复触发、输出上限、归档、权限与连接密钥脱敏。

关键验收场景：改草稿不影响已发布定时任务；运行中发布新版不改变本次运行；同条件走对分支；错误定位到节点；模拟通知零发送；实际未知结果不自动重复发送；每分钟触发仍遵守任务并发限制。

推荐首个交付场景：“查询积压 → 判断阈值 → 邮件/短信告警”，同时提供“每日查询 → 报表邮件”模板。完成这两个闭环后，再扩展节点种类与复杂图能力。
