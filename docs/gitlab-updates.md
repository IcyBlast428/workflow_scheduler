# GitLab 代码更新提醒（第一版）

管理员登录后可打开导航中的「代码更新」，也可使用顶部入口。系统定期读取一个 GitLab 项目的分支，按仓库路径分类变更，在登录后提醒未读更新；文件差异可直接在平台查看，合并请求跳转到 GitLab 处理。本功能只发送 GET 请求，不创建合并请求、不执行合并、不更改仓库、运行目录或当前任务版本。

## 首次连接

展开「GitLab 连接与目录规则」，填写并保存：

- GitLab 根地址，例如 `https://gitlab.example.internal`，支持部署在 `/gitlab` 等子路径。
- 项目数字 ID 或 `group/project`；目标分支默认 `main`。
- 专用只读访问令牌，私有项目建议只授予 `read_api`。此版本通过 API 获取信息，不需要个人 SSH 私钥。未填写令牌时只适用于允许匿名读取的公共项目。
- 自动检查间隔默认 300 秒，允许 60–3600 秒。
- 任务根目录默认 `app/jobs`；公共路径默认 `app/common`、`requirements.txt`、`requirements-databases.txt`，可逐行修改。
- 勾选「自动检查」；需要内网 HTTP 时另外明确勾选 HTTP 选项。HTTP 会明文传输令牌，通常应使用 HTTPS 和受信任证书；内部 CA 可配置为服务端可读文件路径。

保存后可点击「立即检查」。Web 与 Scheduler 必须使用同一个 `WFS_DATA_DIR` 和配置加密密钥；后台定期扫描由单实例 Scheduler 启动。手动检查异步返回状态，页面会自动刷新；外部 GitLab 故障不影响平台健康检查和已有任务执行。

第一版沿用当前项目的管理员权限。普通查看者与旧 operator 账户不会收到更新通知，也不能访问配置、分支或代码差异接口。项目成员级代码访问授权不在此版中。

## 待合并与待部署

1. **待合并**：各分支与配置的目标分支比较，展示尚有文件差异的分支。「去 GitLab 查看合并请求」打开该来源/目标分支的请求筛选页；如果尚未创建请求，需要在 GitLab 中创建。
2. **平台待部署**：目标分支与管理员确认的「平台当前已部署提交」比较，仅显示平台和公共路径差异。
3. **任务待发布**：绑定任务目录、任务编号和确认的「当前已发布提交」后，显示该目录在目标分支中的变化。一个仓库可以绑定多项任务。

所有基线必须使用完整提交 SHA。平台设置提供「使用当前程序提交」，但需要确认这个提交确实属于所连接的 GitLab 项目。旧 ZIP 任务没有 Git 来源信息，不能自动推断其对应提交；应核对原发布来源后填写。未配置基线时，系统仍检查待合并分支，并明确提示无法确认已合并的待部署/发布变化。

目标分支必须包含已确认的部署基线，否则会提示历史或基线需要核对，避免把旧分支或重写历史误认为待升级版本。平台升级或任务发布完成后，再核对并更新对应基线。**“标记本批已读”只关闭这一批提醒，不会改变基线或表示已经上线。**

## 分类与差异

任务绑定目录优先匹配，其次为任务根目录，再匹配公共路径，其余路径归为平台变更。文件移动和删除会同时检查旧、新路径；一个分支涉及多类代码时显示多个标签，不会强制只归一类。公共变更表示需要额外核对影响范围，不会自动判断所有业务依赖。

差异按已获取的完整基线和候选 SHA 固定，显示新增、修改、删除、移动和文本差异，原始代码按纯文本呈现。跳转到 GitLab 的差异链接同样固定提交；合并请求页面中的分支可能继续变化，实际合并时仍应核对 GitLab 的最新状态和规则。

登录成功后和每分钟读取缓存结果；页面隐藏时暂停通知轮询，恢复可见时补读。代码更新页每 5 秒更新检查状态。未读标记按平台账户保存，其他管理员的已读状态独立；「稍后处理」只关闭本次登录中的当前提醒，新一批提交仍会提醒。

## 检查范围与异常

- 每个项目最多取分支 API 排序中的前 100 个分支，超出时明确提示；本版配置一个项目。
- 每轮最多执行 25 项新比对/基线检查，并有软时间预算与逐请求连接、读取超时。固定 SHA 的完整比对复用缓存，后续轮次继续检查尚无缓存的分支。
- 每项比对最多展示 200 个文件、25 万字符文本，单文件最多 8 万字符；API 响应上限 4 MiB。GitLab 返回超时、溢出或省略文件时会显示不完整提示，需到 GitLab 查看完整内容。部分不完整结果会在后续检查重试。
- 读取失败保留上一次结果，同时显示错误和检查时间；不能将错误状态理解为“没有更新”。
- 保存连接配置会清除旧项目的扫描缓存，并使旧扫描结果失效。数据库扫描租约避免 Web 手动检查和 Scheduler 定期检查重复运行；异常中断的租约最多保留 180 秒。
- 本版仅辅助审查，检查不到的分支、共享模块影响、业务正确性和生产部署仍需人工核对。

## 凭据与备份

配置、扫描缓存和每个账户的已读状态保存在共享数据目录的 `gitlab-updates.sqlite3`，无需新增平台数据库迁移。连接配置使用独立用途派生的 Fernet 密钥加密；令牌不会回传浏览器，留空保留已有令牌，也可以明确清除。网络错误不回显服务端错误正文、令牌或认证头；不跟随 HTTP 重定向，以免将令牌转发到其他地址。

`backup_local.py`、`backup_platform.py` 已纳入该数据库的一致性备份，`restore_local.py` 会验证恢复文件。恢复时保留原 `WFS_CONNECTIONS_KEY`（若配置）或 `WFS_SECRET_KEY`。仓库差异属于内部代码，备份仍需按原有数据目录权限保护。

## 验证与启动

```bash
python -m unittest discover -s tests -p test_gitlab_updates.py -v
cd frontend
npm test
npm run build
npm run test:e2e:gitlab
```

GitLab 浏览器验收配置会启动独立临时平台库及本地假 GitLab HTTP 服务，覆盖登录提醒、实际分支/提交比对 API、文件差异、已读持久化、设置和权限；不读取 `.env.local` 或现有项目数据。普通浏览器回归由 `npm run test:e2e` 运行，GitLab 专项由单独配置运行；GitLab CI 会分别执行两组。

本机已有 PostgreSQL 服务时，完成构建后统一重启 Web/Scheduler：

```bash
bash scripts/local_service.sh stop .env.postgres.local
bash scripts/local_service.sh start .env.postgres.local
```

代码与本地模拟服务验证通过后，仍需在自己的 GitLab 上填写真实连接并验收网络、证书、令牌权限与版本兼容性。
