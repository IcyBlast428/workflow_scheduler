## 已修复的问题

1. **任务包的嵌套入口被错误剥离。** 修正 ZIP 成员变量覆盖入口参数的问题，保留显式或继承的 `src/main.py`，同时保留普通导出包去掉外层目录的能力。
2. **任务说明读取绕过安全边界。** README 改为复用受限文件读取，拒绝越界符号链接，读取前检查大小，避免全文件加载后才截断。
3. **快速切换任务时旧请求污染当前页面。** 任务包管理的成功、失败、加载结束和轮询均检查请求代次，旧任务失败不会覆盖新任务状态。
4. **日志搜索无结果被误报为等待输出。** 区分“没有匹配的日志内容”“本次执行没有日志输出”和真正运行中的等待状态。
5. **过期单次调度可能在刷新后再次执行。** 禁止把过去的单次计划重新注册为新 Job，预览也不再列出过期时间；详情页给出重新安排或手动运行的提示。
6. **数值为 0 的调度间隔被静默改成 1。** 仅空值使用默认值，0 进入正常范围校验；覆盖所有 11 类调度规则及不合法日期和表达式。
7. **备份遗漏任务版本和业务输出。** SQLite 和数据库平台备份都纳入 `task-packages`、版本环境和 `task-data`，支持自定义版本目录；恢复保留解释器执行权限，外部业务符号链接明确拒绝而不静默遗漏。

同时完善了测试基础设施：数据库验收使用独立 schema；浏览器验收使用独立 Cookie 名，避免本机相同主机不同端口共享登录 Cookie。通过 `WFS_SESSION_COOKIE_NAME` 可配置名称，默认服务行为保持现有配置。

## 建议继续优化

| 优先级 | 建议 | 原因与实现方向 |
| --- | --- | --- |
| 高 | 明确统一时间基准 | 调度使用 Asia/Shanghai，而部分记录使用宿主机本地时间。部署到 UTC 服务器前应统一存储、查询和显示时区，并增加跨时区回归，避免日统计与任务时间解释不一致。 |
| 高 | 版本与日志保留策略 | 当前保留发布版本、回收站和失败准备目录。增加容量展示、预估清理空间与保留配置，清理时保护当前版本、回滚版本和运行引用。 |
| 中 | 完善弹窗键盘操作 | 统一焦点进入/退出、Tab 焦点限制、Escape 关闭与对话框语义；涉及删除或执行时仍遵循原确认流程。 |
| 中 | 执行详情的名称与反馈 | 弹窗同时显示任务名称和编号；过期单次计划可在列表明确显示“计划已结束”；长耗时发布和依赖检查保留阶段信息，帮助判断是否需要等待。 |
| 中 | 真实通知通道与目标数据库验收 | 在部署环境使用专用测试收件人、网关与生产同类型数据库，验证权限、TLS、发送结果和断网恢复。 |

这些建议需要后续明确设计或目标环境验证，本次没有进行大范围 UI 重构、版本永久清理或生产通道发送。

## 环境边界与恢复说明

本次使用 Windows/WSL Linux、本地 SQLite 与 PostgreSQL 测试库；本地 ODBC 验收不等于生产 GaussDB、集群、高并发或真实邮件/短信网关验收。通知测试验证的是控制逻辑与失败行为。

备份含业务文件、执行日志和账户摘要，应按原备份权限管理。虚拟环境与数据库仍可能引用原路径；恢复应回到原数据/版本路径。跨机器恢复须在启用调度前检查基础 Python、操作系统、架构与依赖。本次新测试证明归档内容完整和恢复解释器可执行，并未向生产数据库导入归档。
