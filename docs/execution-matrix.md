# 任务执行矩阵

从左侧“执行矩阵”进入。使用现有登录及只读权限，数据来自调度器和近期执行历史，无模拟记录；任务详情里的代码查看功能继续使用。

## 阅读方式

- 任务按分组排布，组间留空。组内按 PID 固定排序，各格代表一个任务。
- 底层是所选日期的 00:00；纵向高度代表执行完成时间。跨日执行按完成日期显示，开始时间在详情中展示。
- 绿色成功、红色失败（含超时和重启中断）、黄色执行中。排队、取消及未知状态使用其他颜色。
- 执行中的实例位于当前时间平面。上方空心片表示未来两小时内的下一次计划；详情列表保留当日全部下一次计划。计划不是执行保证。
- 当前日期每 10 秒刷新一次；历史日期同样可刷新，但没有活动实例和未来计划。时间使用服务器本地时间，日期以服务器为准。
- 使用透视投影，近处方格较大、远处较小。围绕矩阵中心旋转，水平和垂直方向均可连续旋转，不限制角度；转到下方或背面仍可查看和选择方格。
- Alt + 左键旋转，向右拖减小水平角度；Alt + 右键缩放，向上放大；Alt + 中键平移。恢复全景只重置相机。
- 普通单击选择任务或执行片，也可通过分组下拉框和记录列表选择被遮挡的片。恢复全景按钮获得焦点时，Alt + 方向键旋转，Alt + 加减号缩放。

## 高频日志的限制

接口 `GET /api/taskinfo/matrix?date=YYYY-MM-DD` 只支持最近 90 天，读取当天完成记录的索引摘要，不读取日志正文。

一次最多绘制 5,000 片已完成记录。超出时按任务和时间段聚合，时间段不小于 15 分钟，随任务数调整。显示总执行次数、成功/失败/取消次数；同一时间段有失败则显示红色。此时一片不再代表一次执行，页面会明确提示。原始日志不被删减，可按时间段进入现有游标分页查询。时间段为半开区间，避免相邻段重复；单次记录使用完整微秒精度的完成时间查询。

最多支持 1,000 个任务，最多读取 1,000 个活动实例，超过活动实例上限会提示。已有归档策略默认保留近期 90 天，不应将自动归档周期设置到小于矩阵窗口；更早记录从调度日志按任务和日期查询。

新增迁移 `005_execution_matrix.sql` 为活动实例状态/创建时间增加索引。部署前按既有迁移流程执行，构建前端后重启实际 API 和调度器服务。

## 测试

- `node frontend/scripts/test-matrix.mjs`：透视近大远小、连续整圈旋转、倒置视角的方格选择、缩放/平移/恢复、分类间距及 100 个任务的固定布局。
- `python -m unittest discover -s tests -p test_execution_matrix.py -v`：SQLite 隔离测试，覆盖授权、日期边界、完成时间、活动实例、聚合失败保留及精确日志跳转。
- 在专用 `.env.postgres.local` 测试配置下运行 `scripts/accept_postgres_test.py`：真实 PostgreSQL 18.1 / ODBC 查询、聚合及日志查询。不能替代生产 GaussDB 驱动与执行计划验收。
