# 任务执行矩阵

从左侧“任务执行”进入。使用现有登录及只读权限，数据来自调度器和执行历史；任务详情里的代码查看功能继续使用。

## 工作区分栏

- 默认“最近结果”，可选择每个任务最近 10 或 25 次：每列一个任务，最新完成结果在上方，任务名在底部，组间留空；横向滚动查看所有任务，25 次可在图表内纵向滚动。绿色成功，红色失败/超时，其他状态使用中性色，无记录为空格。点击方块打开本次详情；归档或旧记录可查看保留的日志摘要。选择“查看任务历史”会带着任务编号进入记录分栏，返回图表保留选择、分类和横向滚动位置。
- “当日轨迹”：保留二维小时热图和三维矩阵，支持历史日期及筛选。
- “执行记录”：支持按任务、状态和日期检索，保留新记录缓冲提示。新地址为 `#matrix?tab=logs`，旧记录链接兼容。
- “执行队列”：仅管理员可见，保留查询、等待原因、取消和执行详情入口；不再占用独立主侧栏入口。旧 `#queue` 和新 `#matrix?tab=queue` 均可使用。

最近结果每 5 秒后台检查，鼠标或焦点在图表内时缓冲变化，避免方块在操作中被替换。`/api/taskinfo/matrix-recent` 接受 `limit=10|25`，默认 10。按任务分别读取近期和归档各最多指定条数，再去重、合并为最新结果。使用现有 `(pid,end_time,id)` 索引，最多 1000 个任务；不读取或传输日志正文，不对整个历史表做全量排名。

## 阅读方式

- 任务按分组排布，组间留空。组内按 PID 固定排序，各格代表一个任务。
- 三维视图已放倒，时间维度沿横向从左至右推进，分类和任务排列在截面上。跨日执行按完成日期显示，开始时间在详情中展示。旧版相机位置不会覆盖新的默认横向视角。
- 绿色成功、红色失败（含超时和重启中断）、黄色执行中。排队、取消及未知状态使用其他颜色。
- 执行中的实例位于当前时间截面。后续空心片表示未来两小时内的下一次计划；详情列表保留当日全部下一次计划。计划不是执行保证。
- 当前日期每 10 秒刷新一次；历史日期同样可刷新，但没有活动实例和未来计划。时间使用服务器本地时间，日期以服务器为准。
- 使用透视投影，近处方格较大、远处较小。围绕矩阵中心旋转，水平和垂直方向均可连续旋转，不限制角度；转到下方或背面仍可查看和选择方格。
- Alt + 左键旋转，向右拖减小水平角度；Alt + 右键横向缩放，向右放大、向左缩小；Alt + 中键平移。恢复全景只重置相机。
- 普通单击选择任务或执行片，也可通过分组下拉框和记录列表选择被遮挡的片。恢复全景按钮获得焦点时，Alt + 方向键旋转，Alt + 加减号缩放。

## 高频日志的限制

接口 `GET /api/taskinfo/matrix?date=YYYY-MM-DD` 只支持最近 90 天，读取当天完成记录的索引摘要，不读取日志正文。

一次最多绘制 5,000 片已完成记录。超出时按任务和时间段聚合，时间段不小于 15 分钟，随任务数调整。显示总执行次数、成功/失败/取消次数；同一时间段有失败则显示红色。此时一片不再代表一次执行，页面会明确提示。原始日志不被删减，可按时间段进入现有游标分页查询。时间段为半开区间，避免相邻段重复；单次记录使用完整微秒精度的完成时间查询。

最多支持 1,000 个任务，最多读取 1,000 个活动实例，超过活动实例上限会提示。已有归档策略默认保留近期 90 天，不应将自动归档周期设置到小于矩阵窗口；更早记录从调度日志按任务和日期查询。

本次复用当前 `schema/gauss.sql` 中已有的索引，无新增表或数据库迁移。构建前端后重启实际 API 和调度器服务。

## 测试

- `node frontend/scripts/test-matrix.mjs`：透视近大远小、连续整圈旋转、倒置视角的方格选择、缩放/平移/恢复、分类间距及 100 个任务的固定布局。
- `python scripts/test_backend.py test_execution_matrix`：真实数据库隔离测试，覆盖授权、日期边界、完成时间、活动实例、聚合失败保留及精确日志跳转。
- `python scripts/test_backend.py test_recent_execution_matrix.RecentMatrixTests`：隔离 PostgreSQL schema 中验证每任务 10、25 条与非法上限、归档合并去重、状态区分和无日志正文。不能替代生产 GaussDB 驱动与执行计划验收。
