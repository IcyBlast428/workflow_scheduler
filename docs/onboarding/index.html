入口适合做什么
总览了解 CPU、内存与任务运行的关系，判断平台整体状态。
任务列表搜索任务、打开说明、手动执行、配置调度、审查代码版本。

账户菜单中的管理入口：平台设置、平台事件、任务示例与文档。普通账户不显示这些入口。

普通用户 / 原操作员

只读查看任务与执行结果。看不到运行、发布等操作按钮属于正常权限控制。

任务维护员

由管理员按任务或分组授权：手动运行、配置调度、查看源码、发布可分别授予；这些授权不隔离只读任务的可见范围。

管理员

管理全部任务，以及账户、业务连接、依赖源、发布规则、审计与存储。

首次登录：使用分配的地址和账号密码，浏览器选择 Chrome 或新版 Edge。IE / IE 模式会被阻止。不同角色看到的菜单和按钮会有差异。

04 / 第一次操作

用一个已发布任务走完完整闭环

适用于有运行权限的人员。只读账户可以跟随查看结果，无需执行。

  1. 1

    找到任务，先读说明

    进入「任务列表」，按名称搜索，必要时用分组或标签缩小范围。点击任务名 →「概览 → 说明与配置」，核对负责人、入口文件、代码版本和最近结果。

  2. 2

    确认本次执行的业务范围

    确认所需连接已授权、参数正确、本次运行不会重复处理不该重复的数据。首次演示选用不写生产数据的教学任务；不要拿不熟悉的业务任务直接试。

  3. 3

    点击「手动执行」

    按钮可能在任务行主操作或「更多」菜单中。任务暂停调度时仍可手动运行；并发名额已满或配置异常时不能触发。点击后查看执行详情，记录本次执行编号。

  4. 4

    确认最终结果和业务输出

    在「任务执行 → 最近结果」点本次方格，或从「执行记录」进入「查看执行」。检查最终状态、日志、输出文件以及实际业务结果。提交成功或已派发都不等于执行成功。

完成标准

能够说明：执行的是哪个任务、哪个代码版本、结果是什么、日志和输出在哪里。

点击后没有回应

先查执行记录，确认原请求是否已经运行，再决定是否重试。不要连续点击生成重复业务操作。

05 / 新增与更新

新任务从 GitLab 进入平台

由管理员或拥有发布权限的维护员操作；管理员先配置 GitLab 项目、目标分支和依赖源。

开发者准备什么

默认扫描 app/jobs/<分类>/<任务>/。只需提交代码、资源与依赖；任务编号由平台自动生成，任务名称与入口在发布页面填写。

daily_report/
  main.py
  README.md
  requirements.txt   # 可选；未提供时自动识别，也可在页面补充

目录中的多层源码和资源可保留。示例可下载，但当前不支持 ZIP 上传发布。

发布人员在页面做什么

  1. 代码合并到目标分支后，在任务列表找到新任务或「GitLab 有更新」提示。
  2. 进入审查，填写任务名称、选择 Python 入口，再点击「获取 GitLab 版本并查看差异」。
  3. 点击「识别并安装依赖」，等到检查通过；失败时先读页面提示；详细 prepare.log 由管理员在服务器版本目录查看。
  4. 核对发布检查摘要；若启用了 CI、时间窗口或试运行要求，先满足条件。
  5. 填写发布说明，点击「发布此版本」并确认。新任务验证后再启用调度；已有任务更新保留原启用状态。

每版本独立依赖

从私有 PyPI 或离线 wheels 准备，运行时复用该环境；不继承平台的第三方包。

检查不运行脚本

语法和依赖通过，只说明版本具备运行条件，不能证明业务逻辑正确。

发布不等于启用计划

新任务默认不启用自动调度。已有任务更新保留调度配置，旧实例继续使用原版本。

06 / 安排自动运行

把“什么时候执行”与“怎样执行”分开设置

保存后同时核对生效状态与未来执行时间，避免只保存配置却没有启用。

什么时候执行

任务列表 → 更多 → 配置

策略适用例子
周期间隔每 N 分钟 / 每 N 小时运行。
固定时间每天、每周、每月、每天多个时间点，或只执行一次。
时间窗口仅在规定时间段内循环。
高级规则熟悉 Cron 时自定义表达式。
怎样执行

任务配置与管理员运行策略

调度配置同时维护负责人、入口、并发上限、执行超时等信息。

管理员在任务详情「配置 → 运行策略」管理默认参数、重试、告警、试运行映射及隔离选项；「参数化运行与按业务日期补跑」可提交相应请求。

自动重试、业务日期补跑默认关闭，只有管理员确认任务可安全重复执行后才可启用。补跑使用当前已发布版本。

示例：每天 05:05 和 06:55 执行

固定时间 → 每天多个时间点 → 添加 05:05、06:55

检查「未来执行时间」 → 勾选「启用自动调度」 → 保存 → 返回详情检查「生效状态」和「下次执行」。时间按 Asia/Shanghai（UTC+8）解释。

想达到的目的应该使用的操作对当前执行的影响
暂时不再按计划触发暂停调度 / 仅暂停当前执行继续；不要把它理解为停止进程。
立即终止运行并暂停任务强制停止终止任务进程并暂停调度；已经写出的业务数据不会自动撤销。
取消一条尚未派发的请求任务执行 → 执行队列 → 取消请求只取消这一次等待，不停止已运行任务，也不关闭调度。

最近结果

默认最近 10 次，可切换 25 次，当前浏览器会按账号记住选择。记录不足时上方留空；组间有间隔，横向滚动查看其他任务。点方格打开执行详情。同一行表示各任务各自的最近第几次，不代表同一时刻。

成功　失败 / 超时　其他状态
查看方格提示或详情确认完整状态，空格代表无记录。

当日轨迹

按日期看二维小时热图或三维矩阵。三维时间轴从左往右；支持分类、时段和异常筛选。执行量大时会按任务与时段聚合，一片可能包含多次执行。

执行记录 / 执行队列

执行记录用于按任务、状态、日期查历史；收到「有新执行记录」提示后主动更新，避免正在查看的行移动。队列仅管理员可见，用于查等待原因与取消待派发请求。

三维操作 Alt + 左键拖动：旋转；Alt + 右键向右 / 左拖动：放大 / 缩小；Alt + 中键拖动：平移。「恢复全景」重置视角。未来计划不是执行保证。

08 / 查明一次执行

先看状态和原因，再看日志与输出

从方格或记录点击「查看执行」，进入本次执行详情。

推荐检查顺序
  1. 执行结果与说明：是成功、脚本失败、超时、取消，还是重启中断？
  2. 时间与来源：什么时候开始、运行多久、手动还是自动、由谁触发？
  3. 代码与环境：本次执行使用的代码版本是什么？不要用当前源码猜测旧运行。
  4. 执行日志：从错误线索向前查上下文，必要时下载保留日志。
  5. 输出文件：预览 / 下载支持的结果文件，再核对业务结果。

大日志如何查看

页面默认打开日志末尾，不一次加载整份文件。可使用「日志开头」「较早一段」「较后一段」「最新日志」。

查看历史分段时暂停追加；「自动滚动」控制跟随。搜索只检索当前加载片段，查完整保留内容请下载。

达到日志容量上限后，后续输出可能被丢弃；文件已清理时，页面会明确提示。下载得到的是仍然保留的日志。

执行记录保留，不代表完整日志永久保留。日志、业务输出和代码版本是不同的存储对象。

给维护人员什么信息

任务编号、执行编号、时间、状态、代码版本、错误片段。复制任务详情链接可帮助对方定位。

什么时候“再执行一次”

先确认上次是否已产生部分业务结果，修复原因后再决定。它会产生新的执行记录。

输出放在哪里

任务应写入 WFS_OUTPUT_DIR，便于按次查看；跨执行持久数据使用 WFS_TASK_DATA_DIR。

任务详情的「执行」组下，管理员看到「执行与输出」，其他账户看到「执行记录」；可见内容以当前授权为准。

09 / 理解与维护任务

在任务详情里按问题找入口

一级分组为概览、执行、配置、发布、安全与审计；没有权限的分组或标签不会显示。

我要解决的问题任务详情中的入口使用提示
任务做什么、如何运行？概览 → 说明与配置 / 执行流程流程图需要源码查看权限；可展开本地函数、定位对应代码。
这次运行为什么失败？执行 → 执行与输出（或执行记录）打开具体执行，核对本次版本、日志、来源和结果。
恢复以前的调度设置？配置 → 配置历史 → 恢复此配置生成新配置版本；沿用所选历史配置的调度启用状态。
查看或回滚代码？发布 → 代码版本 / 查看代码审查差异后选「回滚到此版本」；代码回滚与配置恢复分开。
维护表结构说明和标签？发布 → DDL 与标签保存 DDL 文本不会直接在数据库执行 SQL。
任务可以访问哪些连接？安全与审计 → 连接授权管理员操作；任务默认没有业务库连接授权。
谁改过这个任务？安全与审计 → 操作记录管理员核对操作人、动作、结果和时间。

执行流程图：用来理解代码

当前按 Python 代码静态分析分支、循环、异常与部分本地函数，不运行任务，也没有接入大模型。

它是逻辑概览，不能当作某次运行真实经过的路径；动态调用和外部系统的内部逻辑需要结合源码与日志理解。

更新与回滚的边界

发布后新执行使用新版本，已排队 / 运行实例继续用原版本。回滚代码不会撤销已经写入的业务数据。

任务从 GitLab 删除后，还需在平台确认回收；历史版本、执行记录和输出保留，已接收的执行继续完成。

10 / 管理员日常工作

把任务配置与平台设置分开管理

入口：左下角账户菜单 → 平台设置。普通使用者不需要操作这里。

运行与发布

运行策略 / 发布设置

检查并发与排队策略、运行诊断、维护模式、GitLab 和发布门禁。发布受阻时先读取检查摘要中的具体原因。

连接与依赖

数据库连接 / 依赖仓库

维护业务连接与 Nexus 或离线依赖源。保存连接后，还要给需要它的任务明确授权；源配置变化只影响后续依赖准备。

账户与权限

账户权限

分配只读用户、维护员或管理员角色，维护员按任务 / 分组授予能力。发布白名单可进一步限制发布人员。

审计与存储

审计记录 / 存储清理与备份

检查操作记录、日志与版本占用、备份状态。先预览待清理范围，再确认执行；不要把清日志当作删除执行记录。

生产日志太大时

存储清理与备份 → 执行日志清理

选择保留天数 → 预览 → 核对截止时间、条数和空间 → 输入页面要求的确认文字 → 清理本批。每批最多 500 条；完成后可重新预览。

该操作保留执行记录与历史摘要，不删除业务输出和代码版本；运行中或尚未完整保存的执行受保护。版本环境清理是同页另一项独立操作，按各自预览确认。

服务异常先看哪里

左侧底部接口 / 数据库 / 调度器状态 → 账户菜单「平台事件」 → 平台设置中的运行诊断。绿色表示状态正常，异常时查看具体说明。

备份需要成套保存

平台数据库、data/、logs/ 和配置密钥共同构成恢复依据。文件备份或恢复工具运行完成，不等于业务已恢复成功。

11 / 常见问题

用现象找到下一步

先定位“权限、发布、调度、运行、结果”中的哪一环，再找对应的记录。

遇到的情况先这样检查
我的页面少几个菜单或按钮核对角色和任务授权。总览、代码更新、平台设置、执行队列仅管理员可见；维护员也不是自动拥有所有任务权限。
GitLab 已提交，平台还是旧代码确认代码已合并到配置目标分支，再检查变更、获取版本、审查差异、准备依赖并发布。提交代码不会自动替换已发布版本。
依赖检查失败先读页面失败原因；详细 prepare.log 请管理员到服务器版本目录查看。核对 requirements、私有源与兼容 wheels。平台不会自动改用公网下载。
发布成功，但任务没自动跑核对是否启用调度、配置是否生效、下次时间是否在未来。再查维护状态、排队与并发限制；新任务默认不开自动调度。
请求显示“已派发”这只代表交给执行器。进入对应执行详情查看最终状态和日志，不能据此判断业务成功。
新增记录没有马上出现在列表执行记录会缓冲更新，点击「有新执行记录」。最近结果在鼠标或焦点停留时也会缓冲，避免误点；这些页面不是逐条实时推送。
日志里搜索不到内容搜索范围只有已加载片段。换历史分段，或下载仍保留的日志；已经清理或因容量限制丢弃的内容无法从这里恢复。
任务无法访问业务数据库请管理员检查连接配置、任务连接授权和网络。平台主库正常，不代表业务库连接一定正常。

一场 10 分钟的新手演示

建议使用隔离的教学任务。先演示只读查看，再由有权限的人员完成一次执行。

讲解者照着走

  1. 0–2 分钟用架构图解释代码从哪里来、谁负责运行、结果存在哪里。
  2. 2–4 分钟进入任务列表，打开说明，区分任务、代码版本、一次执行。
  3. 4–6 分钟手动运行教学任务，打开执行详情，检查日志与输出。
  4. 6–8 分钟查看最近结果、筛选执行记录，点开一个异常教学结果。
  5. 8–10 分钟展示调度预览，解释暂停与停止；最后说明权限和求助方式。

新手学会的四件事

  • 能按名字找到任务并读懂说明。
  • 能定位一次执行，分清提交成功和执行成功。
  • 能找到日志、输出，以及本次代码版本。
  • 知道遇到异常时提供哪些信息、联系谁。
演示中的任务名、方格和目录均为教学示例。正式操作以当前登录角色和页面提示为准。

交给运维人员的部署要点

生产目录 /data/workflow_scheduler；根目录唯一的 wfs.service 以 root 用户和组管理 Web 与 Scheduler，无需创建 wfs 系统账户。对外默认 8008，8009 仅供本机内部通信。

普通 HTTP 可使用；生产主库为 GaussDB/DWS。本机 PostgreSQL 用于隔离测试，不能代替生产环境验收。WSL 开发启动方式与生产服务模板分开看。

已有部署的日常检查：在项目目录运行 bash deploy.sh status 或 bash deploy.sh logs。首次部署请按完整部署文档操作。
