# 全新 GaussDB 架构检查

日期：2026-11-04。范围为全新部署，不迁移旧数据。代码未连接实际生产 GaussDB。

## 统一后的存储

平台主库固定为 GaussDB/DWS，生产使用 DWS ODBC 与 Nacos。账户、会话、任务配置、历史、汇总、告警、发布、业务连接密文、授权、请求队列、GitLab 配置、DDL 修改记录与标签均存入平台库。

日志、业务输出、独立依赖环境与代码版本继续保存在共享文件目录；数据库故障时的 JSON 仅用于有界恢复补写。任务默认无业务连接授权。

## 清理内容

- 删除文件数据库适配、专用建表文件和运行时兼容建表。
- 删除 MySQL 平台库切换、平台连接初始化表单；MySQL 任务业务连接保留。
- 删除旧 INI 业务连接回退、DES 模块与依赖、旧业务连接/加密配置和服务器连接示例。
- 删除旧数据和目录任务导入、编号冻结升级工具、编号迁移 SQL、重复基线和专用测试。
- 删除默认任务源码，干净平台没有自动导入的任务。
- 事务示例改为显式授权的业务数据库；DDL 仅展示和留痕，不在任务启动时自动执行。
- 备份统一为厂商数据库 dump 加共享文件。原本地备份/恢复命令名仅委托统一实现，不保留文件数据库逻辑。
- 部署手册、CI、测试准备和数据库检查统一使用新基线，前端资源失效恢复与未保存保护保留。

唯一初始化入口 scripts/init_database.py，唯一 SQL 为 schema/gauss.sql。32 张表一次性创建，重复执行只验证当前基线；非空且无当前版本标记的 schema 拒绝处理，不自动升级或导入。

## 实际 GaussDB 验收边界

本机 PostgreSQL 通过不能替代真实 DWS ODBC、分布式集群、厂商备份恢复、锁等待及性能验收。部署到目标环境时使用新数据库/schema 和新共享目录，按 systemd-deployment.md 初始化、验证，再启用服务；生产禁止本机数据库测试开关。

历史设计讨论仅保留于 docs/archive，不作为当前操作手册。本轮没有推送 GitHub。
