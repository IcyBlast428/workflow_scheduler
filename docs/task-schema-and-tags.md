# 任务 DDL 与标签

任务详情 → DDL 与标签。DDL 查看要求代码查看或发布权限；编辑、导入、提交及标签修改要求任务发布权限。管理员拥有全部权限。标签也显示在只读任务列表。

每个任务使用 `ddl/schema.sql` 管理相关表的定义，可在文件中包含多张表并注明连接标识、用途。平台首次读取已发布文件，后续保存为独立草稿。最多 64 KiB，必须填写修改说明；修改人、时间、全文和版本保存在 admission.sqlite3，显示最近 100 版。载入旧版后重新保存会生成新版本。平台不会执行 SQL，也不会自动从业务库反查 DDL。

GitLab 任务可预览已保存草稿与目标分支的差异，再确认提交到独立 `wfs/ddl/...` 分支。点击返回链接在 GitLab 创建合并请求，合并后沿用现有代码检查、任务发布流程。需要 GitLab 项目 API 写入权限；现有只读令牌无法提交。远端 DDL 改变时先载入远端最新版再编辑；载入会生成历史版本。远端提交、草稿版本或 GitLab 配置改变时旧预览失效。预览 10 分钟有效，提交尝试有唯一凭据，超时不会自动重发；根据页面分支名称在 GitLab 核对。

GitLab 通路通过模拟 API 测试验证，实际私有 GitLab 版本、权限与网关需要在目标环境验收。平台不自动执行合并，也不代表数据库表结构已迁移。

标签为平台元数据，每任务最多 20 项，每项 40 字，支持中文；去除首尾空格并去重。任务列表的“标签”输入框按标签内容筛选，筛选发生在分页前。标签暂不写入 GitLab。DDL 草稿、修改历史、标签和 GitLab 提交凭据都随 admission.sqlite3 备份；部署继续共用同一 WFS_DATA_DIR。
