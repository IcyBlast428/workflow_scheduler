# 日常操作与发布优化

本轮落实整体审视中优先安排的五项：数据库来源展示、发布前检查、维护与执行去重、任务业务连接授权、统一任务详情。

## 数据库连接

连接页展示实际平台库类型、配置来源和运行环境。GaussDB/DWS 生产连接仍由 Nacos 和服务环境管理；本机 PostgreSQL 仍使用原 INI/环境配置。这些环境默认展示来源说明，只有明确展开 MySQL/PolarDB 切换配置后才显示对应表单。切换连接不会搬迁原库数据。

业务连接的管理和测试方式沿用原接口。连接授权在任务详情的「连接授权」页签中配置。

## 维护模式

管理员在任务列表和账户维护页可以进入维护模式，查看运行中和排队中的执行。

- 维护状态保存在共享数据目录的 `admission.sqlite3`，服务重启后继续保留。
- 进入维护后拒绝新的手动执行；自动计划和已排队但尚未启动的执行记为跳过，不启动任务进程。
- 已启动的任务继续完成。进程启动与维护切换使用同一把锁，避免切换期间漏过检查。
- 活动记录和预留名额都归零后，可以安排停止 Web/Scheduler。页面不会自行停止系统服务。
- 结束维护后恢复接收执行；维护期间跳过的计划不自动补跑。需要补跑时先核对业务影响。
- 维护不修改任务的启用配置，不阻止查看日志或准备、发布代码。

此能力依赖单实例 Scheduler 和本机共享数据目录，不是分布式调度租约。维护状态的查询失败会阻止新进程启动，不默认放行。

## 手动执行去重

页面为每次手动执行请求生成编号，在当前浏览器会话中保存。请求超时或响应丢失时再次操作沿用同一编号；服务端按账户与编号保存接收结果，成功的重复请求返回原执行编号。

如果服务在排队与保存接收结果之间中断，原请求标为待核对，不自动重放。页面提供明确的人工确认，再允许清除原请求编号并发起新请求。管理员须先核对执行记录和业务数据。此机制防止同一请求被重复提交，不保证业务副作用恰好发生一次。

API 调用方应在 POST `/api/taskinfo/call_task?pid=...` 的 JSON 中提供 `request_id`，使用 16–100 位字母、数字、下划线或连字符。相同请求必须重用编号，新业务执行使用新编号。未提供编号的旧客户端保持兼容，但不具备跨请求去重能力。接收记录持久保存；不要手工清空数据库来重试未知结果。

## 任务业务连接授权

已有任务默认使用「兼容现有任务」，以免升级后中断依赖旧 INI 的脚本。管理员可逐个切换为「仅允许指定连接」。

限制模式下，平台只向下一次任务执行提供选中业务连接的配置快照，不提供通用业务连接解密密钥；`NewDB` 遇到未授权标识会拒绝，并且不再回退读取旧 INI。未选连接即禁止通过平台 SDK 访问业务连接。平台连接 `platform` 不可授权。正在运行的任务使用其启动时的快照。

限制模式仅继承必要的运行环境和任务路径，过滤平台凭据及其他自定义环境变量。依赖额外环境配置的旧任务需要先调整，再切换限制模式。

这属于可信任务的 SDK 授权和凭据最小化，不是操作系统安全隔离。任务仍与调度器使用同一系统账户，可以自行执行 Python 和访问该账户可读的文件；脚本自行建立的数据库连接也不受 SDK 控制。允许不可信用户发布任意脚本前，需要另行部署系统账户、文件权限与进程隔离。当前版本继续要求审核可信任务代码。

授权只保存连接标识、模式、版本和修改信息，凭据仍由原加密连接库保存。维护状态和授权修改沿用管理员权限、CSRF 与审计机制。

## GitLab 与发布审查

「刷新列表」读取平台现有结果，「立即检查 GitLab」请求异步扫描。页面显示最近完成检查时间、完整性和扫描中状态。网络失败不会表示没有变更。

发布预览增加当前与候选版本、当前调度入口是否存在、依赖变化、环境检查状态、活动实例数和发布后保留的调度状态。该清单是读取预览时的快照，最终发布继续执行服务端状态版本、代码完整性和 GitLab 提交校验。环境检查通过不代表业务验证通过。

差异清单默认仅列出新增、修改、删除的文件，可以取消筛选查看全部文件。独立代码版本入口保留；任务详情内也可直接审查版本，不再需要为此关闭任务上下文。

## 任务详情与备份

管理员任务详情增加「代码版本」「连接授权」，「执行与输出」可在当前详情内查看日志和输出文件。普通用户继续沿用只读详情范围。

`backup_local.py`、`backup_platform.py` 将 `admission.sqlite3` 纳入一致性快照，恢复工具检查其完整性。恢复后先检查维护状态与授权，再启用服务；备份中若处于维护模式，恢复后仍处于维护模式。

本轮没有改变平台数据库结构。无需新增 GaussDB/DWS 迁移；所有 Web 和 Scheduler 应使用同一数据目录并统一更新。旧版本不识别维护模式，回退代码前必须按停机流程处理，不能依赖旧进程遵守新维护状态。

- 后端全量：169 项，167 通过，2 项因目标 GaussDB 未配置及 Windows 专项环境跳过。

- 浏览器：25 个常规场景与 4 个 GitLab 场景验证通过，包含维护期间去重、运行不中断、授权保存、发布检查、详情内日志下载和移动端。页签迁移后的单项回归另行复验通过。
- 本机：统一重启 Web/Scheduler 后，就绪检查中数据库、调度器和存储均正常。
- 浏览器使用独立临时 SQLite 与模拟 GitLab；本轮未连接生产 GaussDB/DWS 或实际私有 GitLab。
