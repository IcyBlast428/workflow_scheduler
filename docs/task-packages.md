# GitLab 任务发布与版本管理

管理员在「任务列表」审查 GitLab 变更，或在任务详情中点击「管理代码版本」。导航中的「任务示例」用于查看、编辑和下载示例；「依赖仓库」独立维护私有 PyPI 设置。ZIP 上传入口已删除，旧接口返回 410。

## 新增、更新与删除

1. **新增**：代码合并到配置的 GitLab 目标分支后，新任务以绿色卡片置顶显示在列表首页。点击「审查并发布 → 获取 GitLab 版本并查看差异」，核对文件和入口，再检查依赖并确认发布。新任务默认不启用自动调度；发布前不会执行业务代码。
2. **更新**：已发布任务在原列表行显示金色「GitLab 有更新」标记。点击后获取完整版本，逐文件审查新增、修改、删除，再检查依赖和发布。保留已有编号、日志和调度配置；当前调度入口不在新代码中时拒绝发布。
3. **回滚**：在版本历史中选择曾成功发布的版本，核对与当前版本的差异，确认「回滚到此版本」。只回滚代码；调度策略可在任务详情的「配置历史」中单独恢复。
4. **删除**：完整目录清单确认目标分支中已删除该任务后，原行显示红色「GitLab 已删除」标记。点击并二次确认后移入回收站，停止后续调度和新手动执行；已排队、运行的实例继续用原版本完成。代码历史、配置、日志和输出目录保留，不提供永久擦除。
5. **旧目录任务**：先通过[一次性停服迁移](platform-releases.md#旧任务的一次性迁移)保留 PID、配置和日志。首次接入 GitLab 时，使用相同稳定编号或在「代码更新」绑定目录，审查本地已发布版本与 GitLab 完整代码的差异后发布。不会根据同名目录覆盖其他编号的任务。

任务发布需要管理员角色。配置 `WFS_TASK_PUBLISHERS=alice,bob` 可进一步限定发布管理员；普通查看者、旧操作员不能读取 GitLab 代码、凭据或发布管理接口。

## GitLab 任务身份与保护

默认发现 `app/jobs/<分类>/<任务>/`；分类可继续增加，任务内部允许多层源码目录。每个任务建议提交 `.wfs-task.json`：

```json
{"task_id":"daily_report","task_name":"日报汇总","main_file":"src/report/main.py"}
```

编号在项目内必须唯一，目录改名时保持编号不变，系统会识别为更新。没有身份文件的旧任务沿用 `<分类>__<目录>`；多个 Python 入口时必须明确 `main_file`。此身份文件参与 Git 内容校验，但不会复制到运行代码中。

只允许发布已合并到配置目标分支的代码。获取和确认发布时都会再次核对目标提交；目标已前进或连接设置已变化时，要求重新检查。任务文件逐一验证 Git blob 校验值，归档文件集合必须与已审查的完整目录清单一致。拒绝符号链接、子模块、Git LFS 指针和危险路径。

仓库目录清单最多 10000 项，并有读取时间限制；读取不完整、网络失败、快照过期或配置改变时禁止发布和删除。缺少 Python 入口但仍有文件的已有任务标记为异常更新，不会当成整项删除。已在本地删除的任务不会因下一轮扫描自动恢复。

旧任务尚未通过 GitLab 发布时，删除提示还需要管理员绑定目录和已部署提交，并且该基线的完整差异中确实存在对应文件删除。仅凭绑定路径在目标分支中不存在，不能发起删除，避免目录填错导致误删。

实现使用 GitLab 官方的[仓库文件树与指定提交目录归档接口](https://docs.gitlab.com/api/repositories/)，实际内网 GitLab 的网络、证书、只读令牌及版本兼容性需要配置后验收。

## 每天在多个时间点执行

在「任务列表 → 更多 → 配置」中选择「固定时间 → 每天多个时间点」，填写 `05:05`，点击「添加时间点」再填写 `06:55`。核对下方「未来执行时间」，勾选「启用自动调度」并保存即可。所有时间按 Asia/Shanghai（UTC+8）解释。

支持每天 1 至 48 个时间点，保存时自动排序并合并重复值。任务仍共用原有并发限制、超时和执行记录；关闭自动调度后只保存计划，不自动执行。该策略会分别在 05:05、06:55 触发，不会额外生成 05:55 或 06:05。普通 Cron 中同时设置小时 `5,6`、分钟 `5,55` 会产生四个组合，因此这种需求应使用「每天多个时间点」。

## 任务目录与依赖

```text
daily_report/
  .wfs-task.json
  main.py
  helpers.py
  sql/query.sql
  README.md
  requirements.txt       # 有第三方依赖时必需
  wheels/*.whl           # 或通过服务端离线依赖库提供
```

保留仓库内任务目录以下的所有层级。不要提交 `.git`、`.venv`、`__pycache__`、`.env` 等本地环境或凭据文件。没有 Python 文件的任务不能发布；单个 Python 文件最大 2 MiB。示例 ZIP 仍可下载，解压后修改稳定编号再提交 GitLab。

每个版本建立独立 Python 虚拟环境，**不会继承平台或原任务环境里的第三方包**。没有 requirements.txt 时只有标准库与环境自带的 pip。现有任务用到平台帮助模块时，也需要列出这些模块使用的第三方依赖。

「依赖仓库」选择 Nexus 后，从配置的私有 PyPI 安装直接及间接 wheel 依赖；不会自动切换到公网。离线模式要求 `package==version` 和全部间接依赖的兼容 wheels，使用 `--no-index --no-deps --only-binary=:all:`。两种模式都执行 `pip check`，拒绝直接 URL、路径和安装参数。依赖准备最多并行两个版本，失败不会改变生效版本。

检查包括 Python 语法、完整文件校验、依赖安装和依赖一致性，**不会执行业务代码**；数据库连接、邮件网关等业务行为需要发布后显式手动验证。

## 数据输出与部署

Linux 上准备好的代码文件和目录设置为只读，并禁止运行时生成 Python 缓存。本次执行的 CSV、JSON 和日志写入 `WFS_OUTPUT_DIR`，可在「查看执行 → 输出文件」浏览、预览和下载；跨执行检查点使用固定 `WFS_TASK_DATA_DIR`。

发布读取指定 SHA 的任务归档，每次创建新版本目录；不对旧运行目录执行 `git pull`、`git clean`、覆盖或递归删除。即使旧代码目录里存在额外输出文件，也不会阻碍更新或删除任务，且不会被带入新版本。旧文件仍留在原位置；原有业务输出应逐步改写到上述数据目录。GitLab 仓库中的平台源码、公共模块仍由平台部署流程管理。

入口工作目录为包根目录 `WFS_TASK_ROOT`，支持有 __init__.py 的包入口、src/ 布局和相对导入。多层目录发布、目录处理选项、输出保留与权限详见[复杂项目与输出文件](task-outputs-and-projects.md)。

版本放在 `<WFS_DATA_DIR>/task-packages/<PID>/releases/<版本>/`，与平台 Git 发布目录分开。每个排队或自动调度实例固定代码路径和解释器路径，发布切换不会让旧实例读到新模块。解释器使用服务器已安装的 Python 基础运行时；跨 Python 大版本升级仍需按部署计划验证。

发布先记录意图，再切换调度器，收到确认才显示生效；失败恢复上一版本。服务重启发现未完成发布会恢复之前版本，未完成依赖准备显示失败，可重试。新依赖准备使用新的尝试目录，避免中断过程覆盖重试结果。

| 设置 | 默认 | 说明 |
|---|---|---|
| `WFS_TASK_RELEASE_DIR` | `<WFS_DATA_DIR>/task-packages` | 版本目录，Web/Scheduler 设置必须一致 |
| `WFS_TASK_WHEELHOUSE` | 不设置 | 管理员维护的离线 wheel 目录 |
| `WFS_TASK_PUBLISHERS` | 不设置 | 允许发布的管理员用户名，逗号分隔 |
| `WFS_PACKAGE_UPLOAD_MB` | 64 | GitLab 任务归档下载上限 MiB（保留兼容配置名） |
| `WFS_PACKAGE_EXPANDED_MB` | 256 | 解压文件总大小上限 MiB |
| `WFS_PACKAGE_MAX_FILES` | 2000 | 文件数上限 |
| `WFS_PACKAGE_PREPARE_SECONDS` | 300 | 每条环境准备命令超时，30–1800 秒 |

上线前运行 `python scripts/migrate.py` 确认 **007_task_packages.sql**，再重启单实例调度服务和 Web 服务。GitLab 发布操作通过 Web 转发到 Scheduler，沿用会话、CSRF、审计和管理员发布权限。GitLab 来源随任务/版本登记保存在原有 payload，无需新数据库迁移。

数据库登记表为 `wfs_package_tasks`、`wfs_task_releases`。`backup_local.py` 与 `backup_platform.py` 会包含默认版本目录、独立依赖环境和 task-data；设置了自定义 `WFS_TASK_RELEASE_DIR` 时，备份命令需加 `--releases <该目录>`。归档统一放入 `data/task-packages`，恢复时应复制回原版本目录与原数据目录，因为数据库和虚拟环境仍引用原路径。恢复到另一台服务器时，基础 Python、操作系统和架构必须兼容，并在启用调度前验证解释器与业务依赖。备份不接受指向外部业务文件的符号链接，此类文件需单独备份；环境中的 Python 链接会复制为可执行文件。已发布版本、回收站和失败准备目录均不会自动清理；持续运行时按磁盘容量规划保留空间，本版本不提供永久删除按钮。

## 接口

- `GET /api/taskinfo/packages`：任务与回收站；加 `pid` 返回任务状态和最近 50 个版本。
- `POST /api/taskinfo/packages/upload`：已移除，返回 410。
- `GET /api/taskinfo/packages/gitlab`：获取缓存任务变更，不执行外部网络请求；`POST` 携带变更 `id` 和 `stage/delete` 操作。
- `GET /api/taskinfo/packages/preview?pid=…&version=…`：清单、当前版本差异；加 `path` 返回受限文本差异。
- `GET /api/taskinfo/packages/download?pid=…&version=…`：只下载该版本代码包，不包含虚拟环境和业务数据。
- `POST /api/taskinfo/packages/action`：`prepare/publish/rollback/trash/restore`；切换或删除携带当前 `revision`，过期状态返回 409。旧 `import` 返回 410。

任务代码是管理员可信代码。本功能提供版本隔离和发布检查，不是执行不可信代码的安全沙箱。
