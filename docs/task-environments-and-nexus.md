# 任务环境、示例管理与 Nexus

## Python 运行关系

平台的 Web / Scheduler 使用部署时安装的平台 Python 环境。通过任务发布页面管理的每个任务版本，在“识别并安装依赖”阶段创建自己的 `environment-<准备编号>` 虚拟环境，不继承平台或其他任务的第三方包。虚拟环境基于 Scheduler 当前使用的 Python 主版本，不代表每任务可选择不同 Python 版本。

发布成功后，每次执行均由 Scheduler 使用该版本环境的解释器启动独立 Python 子进程；进程结束后退出，但虚拟环境保留，下一次执行复用，不重复安装依赖。同一版本的并发执行各有进程，共享同一个环境；不同任务、不同版本的环境分开。回滚使用旧版本已经准备好的环境。

所有运行任务均来自已发布版本，并使用该版本的独立虚拟环境。任务通过 GitLab 完成审查、依赖检查和发布，运行时不会回退到平台解释器。虚拟环境隔离 Python 依赖，不隔离操作系统权限。

## 只提交代码，自动准备依赖

没有 `requirements.txt` 时，平台静态读取任务 Python 文件中的导入，排除标准库、本地模块和相对导入，并检查引用的公共 SDK 模块在导入时所需的依赖。例如 `requests`、`pandas` 和 `app.common.mail` 会识别出 `requests`、`pandas`、`SQLAlchemy`、`urllib3`；其间接依赖交给 Nexus 中的包元数据解析。不会为识别依赖而执行任务或发送邮件。

操作步骤：在任务版本页核对「运行依赖」→「识别并安装依赖」→ 检查通过后「发布此版本」。页面可展开查看包名和来源文件；安装后显示实际锁定版本。提供了 `requirements.txt` 则优先按文件安装，保留版本和环境条件。

导入名不一定等于仓库包名，例如 `PIL` 对应 `Pillow`、`yaml` 对应 `PyYAML`。常见名称已内置映射，其他名称按同名包尝试并提示核对。可在「补充或调整依赖」填写本版本完整清单，支持版本范围；无需再向 GitLab 提交依赖文件。页面清单只保存在版本记录和版本目录，不修改原代码或 Git 校验值。

动态变量导入、可选功能、运行时选择的数据库驱动或 Excel 引擎等，无法仅凭普通 import 完全确定。平台会提示可识别的动态/可选导入；这些依赖可在页面补充。识别覆盖任务内所有 Python 文件，建议仅提交该任务所需的源码。自动/页面配置模式安装后会检查识别到的顶层模块是否存在，但不会导入执行模块，因此仍需手动验证实际业务逻辑。

已发布任务遇到缺包：在「管理代码版本」选择当前版本 →「用原代码重新准备依赖」→ 核对或补充依赖 → 安装并发布。原目录、任务编号及调度保留，已运行/排队的实例继续使用旧版本。不会在失败任务中自动安装并重跑，以免重复发送邮件或写数据。GitLab 任务仍遵守目标提交校验；目标分支已前进时，应获取最新任务版本。

## Nexus 配置与使用

管理员在「账户菜单 → 平台设置 → 连接与依赖 → 依赖仓库」选择 Nexus 并保存：

```text
安装方式：Nexus 私有仓库
索引地址：http://nexus.immp.icbc/repository/pypi-hosted/simple/
认证账号：留空
认证密码：留空
CA：留空（此地址为 HTTP）
```

地址填写 `http://nexus.immp.icbc/repository/pypi-hosted` 时自动补全 `/simple/`，遵循 [Sonatype PyPI 配置方式](https://help.sonatype.com/en/configure-pypi-with-nexus.html)。生产仓库实际连通性需在可以访问内网的 Scheduler 主机上验证。这里没有声称已经访问或验收生产内网仓库。

Nexus 模式只需包含代码和必要资源，requirements.txt 可选，不必再打包 wheels：

```text
main.py
requirements.txt  # 可选，需要固定版本时提供，也可在页面调整
```

requirements.txt 示例：

```text
requests
pandas
SQLAlchemy
urllib3
```

完整流程：代码合并到 GitLab 目标分支 → 任务列表审查变更 → 获取指定提交 → 查看文件差异和自动识别的依赖 → 识别并安装依赖 → 创建版本虚拟环境 → 从 Nexus 安装依赖 → pip check → 记录 dependencies.lock.txt → 确认发布 → 手动执行验证 → 启用调度。准备阶段不会运行任务入口，失败版本不能发布。缺包提示会给出包名，仓库权限、连接失败和版本冲突分别提示；详细错误保存在版本目录 prepare.log 中。

管理员只需配置一次仓库。已有的离线模式不会被自动改为在线；尚未开启 Nexus 时，页面会提示管理员配置。离线模式仍支持完整固定版本清单和本地 wheel 目录。

Nexus 模式使用一个索引，不设置额外公共索引，不读取服务主机已有的 pip 配置，避免已有 extra-index 设置混入公共源。[pip 文档](https://pip.pypa.io/en/stable/cli/pip_install/)说明 extra-index 可能造成同名依赖选择问题。HTTP 仓库仅针对配置主机添加 pip trusted-host；HTTPS 保持证书校验，可配置内部 CA。

当前安装匹配 Python / 系统 / CPU 的 wheel，不在线编译源码包。pypi-hosted 仓库需要包含全部间接依赖的兼容 wheel；若内部 hosted 仓库没有这些依赖，应由管理员预先上传，或在 Nexus 侧提供包含 hosted / proxy 的 group 仓库，再调整索引地址。不会因私有仓库缺包而自动切到公网。

安装结果保存在版本目录 dependencies.lock.txt，便于核对实际版本；现有环境在运行和回滚时复用。若依赖文件使用范围而非精确版本，重新准备可能解析到不同间接版本；如需重建结果一致，应将验证后的完整版本锁定纳入下一任务包。

## 示例维护与数据保留

管理员可编辑类型名称、说明、提示、下载文件名、代码语言、源码，或新增示例类型。代码展示使用语法高亮和 HTML 转义，复制与下载保留原始文本；保存示例不会执行代码。当前编辑若遇到其他管理员已修改的版本，会返回冲突并保留本地草稿。

示例与仓库配置保存于共享 GaussDB 平台状态表。仓库配置使用从平台配置密钥派生的独立密钥加密；密码不回传前端。准备依赖时如需要认证，使用临时 netrc 文件，安装结束即清理，不把密码写入命令参数或任务环境；准备日志会隐藏已知认证密码。当前生产地址无需认证。

Web 和 Scheduler 必须挂载相同数据目录，仓库配置保存后无需重启，下次环境检查读取新设置。配置不会修改已发布版本的依赖环境。仓库配置随 GaussDB 原生备份保存；恢复时需要保留原配置密钥。升级代码不自动覆盖已保存的示例。
