# 性能优化与数据库连接管理升级

本版继续使用一个平台 GaussDB/DWS 数据库保存账户、任务、队列、执行记录和配置，同时允许任务通过 `NewDB` 访问多个业务数据库。平台库与业务库分别管理，即使使用同一台数据库服务器，也应分别规划账号、权限和连接预算。

本说明适用于已经运行当前 GaussDB/DWS 架构的部署。它不负责把旧架构数据导入新平台，也不会自动把现有数据迁移到另一台数据库。

## 本次四项优化

| 范围 | 变化 | 保留的边界 |
| --- | --- | --- |
| 调度与队列 | 运行策略共用有界缓存，保存后通过共享版本标记失效；全局并发已满时停止无效派发和状态改写 | 真正启动前仍检查维护状态、取消、期限及名额；不会修改现有运行策略 |
| 平台连接 | 每个 Web / Scheduler 进程拥有有上限的连接池；连接借还、超时及等待耗时可观测；页面可编辑平台连接来源与参数 | 平台仍为 GaussDB/DWS；编辑保存为待重启配置，不会在线迁移数据库 |
| 热点查询 | 增加全局开始时间、全局执行创建时间索引；概览历史标记共用短缓存 | 新实时标记仍逐次合并；已有数据库需在维护窗口补索引 |
| 日志与历史 | 新执行只在数据库保留小摘要；归档按批次复制、完整比较后事务搬移，可设时间和批次数量预算 | 完整保留日志文件与告警原有内容额度不变；归档位于同一数据库，不永久删除记录 |

详细参数见 [调度与容量](task-dispatch.md)、[日志和历史存储](performance-storage.md)、[统一业务数据库连接](business-database-connections.md)。

## 页面管理方式

「系统管理 → 数据库连接」分为两个入口：

- **平台数据库**：查看当前生效配置、待生效配置与连接池状态。可以沿用服务配置/Nacos，也可以直接在页面填写自定义地址、端口、库名、Schema、账号、密码、ODBC 驱动名称及连接池参数。只有内置管理员（`WFS_ADMIN_USERNAME`，默认 `admin`）可以测试和保存；其他管理员只读，非管理员不能访问该页面或接口。
- **业务数据库**：搜索、新增、编辑和测试任务使用的连接；查看连接类型、环境标签、关联任务及启停状态；分别设置连接池参数。

业务连接标识是任务代码使用的稳定名称。例如 `orders_mysql` 与 `reports_postgresql` 可以使用不同数据库类型，同一个任务获得授权后可以分别创建两个 NewDB 实例。

平台连接不出现在任务的业务连接授权里。任务不能使用 `NewDB("platform")` 访问平台主库；需要访问部署在同一服务器上的业务 Schema 时，仍应建立独立业务连接并授予最低必要权限。

## 平台连接配置与重启

平台连接引导配置不能只存放在它所指向的数据库里。本版将页面保存的配置加密存放在：

```text
/data/workflow_scheduler/data/platform-connection.enc
```

实际位置随 `WFS_DATA_DIR` 改变，也可用 `WFS_PLATFORM_CONFIG_FILE` 显式指定。加密密钥使用固定的 `WFS_CONNECTIONS_KEY`，未设置时使用 `WFS_SECRET_KEY`。密钥需与备份分开安全保管；丢失原密钥后不能解密已有配置。

保存前先验证目标连接和平台表结构；只测试，不自动建表。页面保存的是**待生效配置**，现有服务继续使用当前目标。完成完整的 `wfs.service` 重启后，新配置才成为生效配置。只重载页面、刷新连接状态或重建某个 Web 工作进程不应成为切换数据库的操作方式。

修改地址、库名或 Schema 前，管理员需要先完成数据迁移，并核对账号、任务、队列、授权、密钥和任务文件的一致性。**连接测试通过只证明目标可连接且具有本版表结构，不证明原有数据已经迁移。**

服务启动时会在 `data/platform-runtime/service-<随机标识>.enc` 创建本次启动使用的加密快照，所有 Web / Scheduler 子进程通过 `WFS_PLATFORM_ACTIVE_CONFIG_FILE` 使用同一快照。正常完整退出会清理运行快照；该快照不是供管理员编辑的配置文件。

平台备份新增两个明确区分的证据位置：

- `bootstrap/platform-connection.enc`：已保存、供下次完整重启使用的配置。自定义 `WFS_PLATFORM_CONFIG_FILE` 也收集到这个固定位置，不把原外部绝对路径写入清单。
- `bootstrap/platform-active.enc`：仅在调用备份时能读取指定的 `WFS_PLATFORM_ACTIVE_CONFIG_FILE` 时收集，代表该服务启动快照。正常停服务后快照可能已清理，清单会明确标记未包含，不能把待生效配置当作实际生效配置。

备份清单分别记录两份配置是否包含及各自校验值，密钥仍不打包。恢复工具验证密文文件校验值，只解压到 `bootstrap`，**不会把配置自动应用到恢复后的服务**。实际数据库备份来源以清单中的数据库、Schema 及运维指定的导出目标为准；恢复前必须核对目标，避免把仍指向原生产库的配置直接用于演练环境。

如果存在待生效配置但备份进程没有明确的生效快照，备份仍可完成，但不会连接该待生效目标写入数据库回执；清单记录 `backup_receipt.written=false` 及原因。提供生效快照或使用未保存页面配置的原服务配置时，均先核对主机、端口、数据库和 Schema，匹配后固定该目标写入回执。无法核对、目标不一致或容器导出端点不明确时也跳过。允许写入的清单将 `written` 留为 `null`，表示备份封装完成后才尝试写入，清单本身不冒充数据库写入成功证明；成功的数据库回执才是写入凭据。

配置回退时同样先确认目标数据，然后保存正确配置并完整重启。如果配置错误导致服务无法启动，可由运维在服务停止期间恢复此前备份的加密配置与原密钥，核对目标后重新启动。

## 连接池与监测

平台池和业务池分别计数，连接按需创建。池容量不是启动时预先创建的连接数量，也不是整个数据库的 `max_connections`。

| 池 | 默认池内上限 | 默认额外连接 | 说明 |
| --- | --- | --- | --- |
| 每个 Web 进程的平台池 | 5 | 3 | 标准生产部署有 2 个 Web 工作进程 |
| Scheduler 进程的平台池 | 10 | 5 | 标准部署为单个 Scheduler |
| 新业务连接，每个任务进程 | 1 | 1 | 既有业务连接保留已保存参数 |

标准部署的默认平台池容量合计为 `2 × (5 + 3) + (10 + 5) = 31`。这只是本平台各进程的配置额度，不包含任务业务连接、数据库管理工具和其他应用，也不是生产所需连接数的测量结果。

任务每次执行都是独立进程。业务池复用的是这一次执行内部的连接，不会跨分钟或跨进程共享。一项任务如果会同时持有多个连接，需要按实际并行度配置，不能仅依据任务总数分配连接。

平台页面汇总近期 Web / Scheduler 进程上报的使用中、空闲、等待和超时信息，计数随进程重启重置。连接等待 P95 包含借连接过程中的开销，应结合真正建连时间、查询时间和数据库锁等待判断。业务池接口当前只展示响应请求的 Web 进程，不能替代任务进程及数据库端的全局连接监控。

## 统一使用 NewDB

新任务的业务访问入口为：

```python
from app.common.database import NewDB

with NewDB("orders_mysql") as db:
    orders = db.query(
        "SELECT id, amount FROM orders WHERE business_date = ?",
        ("2026-11-15",),
        as_dict=True,
    )
```

先在页面创建连接，再到任务详情的连接授权中勾选该连接。任务不需要保存账号密码。修改业务连接后，下一次任务执行读取新配置；已经运行的任务仍使用启动时冻结的配置。

支持的适配器包括 MySQL/PolarDB/MariaDB、PostgreSQL、GaussDB/DWS ODBC、ClickHouse。GaussDB/DWS 还需要安装相应的系统 ODBC 驱动。Web 测试环境和任务独立环境都必须具备需要的驱动及可读取的证书。页面添加连接不会自动安装驱动。

同一种已支持类型的新实例可以直接在页面添加和编辑。全新的数据库引擎类型需要先加入经验证的适配器和驱动，再开放为页面选项。NewDB 统一连接、参数和事务入口，业务 SQL 仍须符合目标数据库方言，不能把某一种数据库的语句原样当作全部类型通用语句。ClickHouse 不提供本接口的事务回滚能力。

新增发布的 Python 源码会检查直接导入原生数据库驱动、直接创建 SQLAlchemy 引擎和直接访问平台 GaussDB 的行为，发现时显示文件和行号，要求迁移到 NewDB。新版本准备和正常发布也会重新检查。已经发布的任务和历史回滚保留兼容，不会因升级平台立即停止执行；重新发布时应迁移旧代码并准备新的任务环境和 SDK 快照。

这是可信任务代码的访问规范检查，不是可以隔离任意 Python 代码的安全沙箱。动态代码、第三方包内部访问或自行建立网络连接仍需要代码审核及适当的运行环境隔离。

## `/data/workflow_scheduler` 生产升级步骤

### 1. 备份和维护窗口

确认平台数据库产品及版本、当前数据目录、服务使用的固定密钥和 ODBC 驱动。先完成数据库与文件备份，保存当前版本及平台连接配置。加密连接配置与任务业务连接密文都依赖原密钥；密钥不应提交到 Git 或放入公开备份。

安排维护窗口，暂停新增执行，并确认正在运行的任务和待派发队列。服务停止或重启不会自动补齐停机期间所有计划，重要业务需按其补跑规则处理。

### 2. 更新代码与依赖

将经过测试的版本部署至 `/data/workflow_scheduler`，保留原 `data`、任务发布目录、日志、服务环境文件和密钥。按原部署流程更新平台依赖。需要新增业务数据库类型时，再为 Web 连接测试器与相应任务环境安装匹配驱动；不要把所有任务环境直接替换为同一个环境。

以下命令使用与 `wfs.service` 一致的运行账号、Python 环境和环境配置。示例中的路径对应默认生产目录；自定义目录应相应替换。如果已暂存另一目标库的配置，先明确独立运维命令的连接目标；需要操作旧目标时，应显式使用经核对的旧配置快照作为 `WFS_PLATFORM_ACTIVE_CONFIG_FILE`，不能假定独立命令会继承已运行服务的进程内配置。

### 3. 预览并补齐热点索引

```bash
cd /data/workflow_scheduler
.venv/bin/python scripts/upgrade_performance_indexes.py
```

确认缺失索引及维护窗口后：

```bash
.venv/bin/python scripts/upgrade_performance_indexes.py --apply
```

脚本只创建缺失的 `idx_wfs_run_start_id` 和 `idx_wfs_executions_created_id`，重复运行不会重复创建，不会清空或搬移业务数据。建索引可能阻塞写入，需要评估大表规模、可用空间和实际 GaussDB/DWS 版本。新安装数据库已包含这两个索引。升级在 GaussDB/DWS 上锁定版本表来串行执行，原生 PostgreSQL 验收使用事务咨询锁；两者都会在失败时回滚本次索引事务。

### 4. 完整重启并检查

```bash
systemctl restart wfs.service
systemctl status wfs.service
```

确认就绪接口、登录、任务列表、执行记录和业务连接管理能够访问。平台数据库页面应显示预期的生效配置及连接池状态；在匹配的真实数据库上测试需要使用的新连接类型。先选择可安全执行的测试任务核对参数查询、提交/回滚、日志、授权与取消，再恢复正常调度。

### 5. 设置存储策略与观察容量

历史自动归档默认关闭。需要时在存储页面开启，先以默认小批次观察完成耗时、积压和数据库负载。归档位于同一库，减少在线历史表负担，**不会释放数据库总占用空间**，也不会永久删除历史。尚未完成小时汇总的旧记录会先保留在线，等待后台汇总完成后再归档，避免出现历史仍在但统计丢失。

数据库摘要的默认 2 KiB / 16 KiB 只作用于后续完成的记录，不会改写已有历史。文件日志保留规则独立于摘要和历史在线保留天数；文件到期后只能查看数据库摘要。

升级不会自动把现有运行并发改大。约 75 次/分钟意味着平均启动频率 1.25 次/秒；若仍使用默认 1000 毫秒启动间隔，理论启动速度本身就不足。平均并发至少约为 `1.25 × 平均执行秒数`，还需给其他任务、开始/结束记账和高峰预留余量。结合业务数据库负载逐档测试并发、启动间隔和错峰，当前 20 个执行名额上限不等于所有一分钟内完成的任务都能按时启动。

## 验收范围

本地测试库验证协议、连接复用、事务、查询、策略、归档与管理页面的行为。实际 GaussDB/DWS、ClickHouse 等目标服务端和系统驱动的连接兼容、证书、事务及性能仍需实库验收。页面测试成功也不能代替业务 SQL 验证。

容量验收至少记录任务平均/P95 耗时、排队时间、启动延迟、平台池等待、数据库慢查询与锁等待、CPU/内存/磁盘 I/O，以及日志与历史每日增长量。业务库和平台库同机时，这些指标需要在业务查询同时运行的情况下观察。常规功能回归通过不能单独证明生产持续吞吐。
