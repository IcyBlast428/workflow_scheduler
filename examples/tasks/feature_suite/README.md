# 功能示例体验指南

五个可直接运行的示例安装在本机“功能示例”分组，自动调度关闭。完整代码可在“任务示例 → 完整项目示例”下载，也可在当前目录复制到 GitLab。每个目录的 settings.json 描述建议策略，平台不会自动读取此文件；本机安装脚本会应用这些值。

| 示例 | 核心能力 | 体验步骤 |
| --- | --- | --- |
| 多文件参数报表 | 参数、资源文件、可展开流程、CSV/JSON、源码版本 | 手动执行；region 从 CN 改 EU；查看报告与流程 |
| 多表事务与 DDL | 两张表、事务、参数绑定、DDL 编辑历史 | 执行后重跑；simulate_rollback=true 观察回滚；在 DDL 与标签中查看定义 |
| 失败与自动重试 | 幂等声明、自动重试、失败记录与告警 | 手动执行预期失败；本示例已开启一次自动重试，约 10 秒后生成成功重试；模拟开关设 false 可直接成功 |
| 业务日期补跑 | 历史日期、固定日期结果、重复执行不追加 | 选择过去日期提交补跑，多次补同日查看同一结果文件 |
| 排队与资源观察 | 进度日志、持久队列、并发、超时、取消、CPU | 参数化执行提交多个请求；seconds=5，CPU 默认 0；seconds=25 超过本机配置的 20 秒超时；cpu_seconds=1 可短暂观察曲线 |

## 推荐顺序

1. 打开任务详情 → DDL 与标签，检查标签与 SQL，修改后填写说明并保存，查看历史版本。
2. 手动执行报表、事务、补跑示例，查看执行编号、日志与输出文件。每次执行输出独立，跨版本的业务文件在任务数据目录。
3. 用失败重试示例观察失败记录、待重试请求、成功执行。没有配置通知网关时不会收到真实通知；实际通知需先配置测试接收人和通道。
4. 在排队示例 → 运行策略 → 参数化执行中连续提交多个请求，去执行队列查看等待原因。普通“手动执行”满额时直接提示，不进入持久队列。暂停调度不等于停止运行；强停会影响正在运行的示例。
5. 在运行策略显式配置 30–60 秒错峰，再启用示例的调度，观察原计划时间与实际开始时间；体验完可暂停调度。安装时不会启用任何定时计划。

## 需要环境配合的能力

- **真实业务库与连接授权**：business_connection 是额外模板，不自动安装。配置测试连接与依赖后，通过 GitLab 发布。database_transaction 需要授权业务连接和预先审查执行的 DDL，不自动安装。
- **GitLab / 代码版本 / DDL 联动**：本机生成的五个任务来自本地安装，没有 GitLab 关联。若要关联到已有本机 PID，在 GitLab 配置的任务目录绑定中填写当前任务 ID 与对应仓库目录，再按既有扫描、发布流程建立 git_source；也可换独立目录作为新任务发布。修改代码 → 分支 → 差异审查 → 合并 → 发布 → 回滚；DDL 在详情中预览后提交独立分支，不自动执行 SQL。
- **私有 PyPI 与离线依赖**：上述五例仅用标准库，无需联网安装依赖。依赖仓库功能可用已有 Nexus、离线依赖示例及业务连接模板体验。
- **systemd 隔离**：五例安装为冻结 SDK 的受管版本，并采用无业务连接的指定授权。先检测隔离能力，再为报表或排队示例显式启用 systemd，设置 CPU=50%、内存=128 MiB；默认仍为普通进程。能力检测不通过时保持关闭。外部业务连接另配测试授权。
- **维护与权限**：用排队示例运行时进入维护，观察运行继续完成、新请求拒绝和已有队列期限；新建只读用户与任务维护员检查任务操作权限。不要为演示修改现有用户权限。
- **备份与清理**：通过系统管理查看版本占用与备份记录；实际清理仍遵循维护及保护规则，无需为体验强制清理保留版本。

## 安装与验证

本机已安装。再次运行 `scripts/install_feature_examples.py --env-file <服务环境文件> --install` 会保留已存在的同名分组任务，不覆盖用户修改。该工具使用内部受管版本流程，不新增 ZIP 上传接口；生产发布门禁仍会生效。环境文件包含连接配置，不提交仓库。

`python -m unittest discover -s tests -p test_feature_examples.py -v` 在临时目录检查输出、事务回滚、重试分支和同日补跑覆盖。
